The design problem

Arabic affects more than alignment. Labels expand differently, line heights need room for diacritics, directional actions change, and Latin data must remain readable inside an RTL sentence. Treating Arabic as a final translation step makes those decisions expensive to correct.

Nasaq takes that as a design premise. The case study does not claim a participant study or production rollout.

Implementation decisions

01

Direction belongs to context

A manually reversed layout is quick to demonstrate but becomes difficult to maintain. Nasaq uses lang and dir, logical spacing, and bdi for mixed text. Each language keeps meaningful reading and focus order.

Tradeoff: The consumer must still mark the language and direction correctly.

Inspect the implementation
02

Type roles stay consistent

Arabic uses Almarai; English uses Inter. Body text keeps the same role name with language-specific line height. This lets a component keep its meaning without forcing the two scripts into the same rhythm.

Tradeoff: More typography values to maintain, with a clearer contract for each language.

Inspect the implementation
03

Native controls carry behavior

Buttons, inputs, selects, disclosures and dialogs use native HTML. The shared runtime adds the behavior that HTML does not provide by itself, including tabs and tooltip dismissal.

Tradeoff: Native controls inherit some platform differences. The gain is a smaller custom interaction layer.

Inspect the implementation

Arabic and accessibility

The library uses contextual direction rather than manually reversing controls, with a font and reading rhythm for each language. The quality record separates verified behavior from the screen-reader audit that has not yet been recorded.

What the project demonstrates
The working output includes 18 components with state galleries, typed tokens, a local installable package and a read-only MCP server. These are implementation results. They do not establish customer adoption or commercial impact.
  • Read the verification record

What needs to be learned next
Keep. Keep contextual direction and native controls. The implementation shows how reading order and interaction contracts remain explicit in both languages.
Change next. Before expanding the library, I would document one actual component proposal from need through review decision and migration. A filled example would make the current contribution policy easier to assess.
Question to test. Observe whether a designer and a developer can complete the same interface task, explain the states and hand it off without assistance. Record errors, questions and time before making an efficiency claim.
